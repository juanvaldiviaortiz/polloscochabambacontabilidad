Documentación Técnica de la API

Especificaciones para la integración con el ecosistema de Pollos Cochabamba (Entorno Red Local / LAN)

1. Introducción

La Pollos Cochabamba API es un sistema desarrollado en Flask sobre una base de datos MariaDB, diseñado para gestionar los recursos humanos, de marketing y movimientos financieros de la empresa.

Servidor Backend

Flask (Python)

Base de Datos

MariaDB

Formato

JSON REST API

Funcionalidades principales:

  • Registro e inicio de sesión de usuarios.
  • Gestión de empleados.
  • Gestión de capital y presupuestos de marketing.
  • Control y auditoría de movimientos financieros.

2. Configuración para Pruebas en Red Local (LAN)

Para permitir que otros dispositivos dentro de la misma red local puedan consumir la API, el servidor Flask debe ejecutarse vinculándose a la IP universal 0.0.0.0:

# En el archivo principal de Flask (app.py)
if __name__ == '__main__':
    app.run(host='0.0.0.0', port=5000, debug=True)

Dirección IP del Servidor en LAN (Ejemplo): http://192.168.1.100:5000 (Reemplazar 192.168.1.100 por la dirección IP asignada a su servidor mediante ipconfig o ifconfig).

3. Acceso y Autenticación

La API implementa seguridad mediante autenticación basada en clave de API (API Key). Esta clave debe incluirse en los encabezados HTTP de cada solicitud en el parámetro x-api-key.

GET /empleados HTTP/1.1
Host: 192.168.1.100:5000
x-api-key: mi_api_key_segura

4. Rutas o Endpoints

POST /login

Inicia sesión en la plataforma validando credenciales.

Body (JSON):

{
  "email": "user@mail.com",
  "password": "1234"
}

Respuesta:

{
  "message": "Login exitoso"
}

POST /registro

Registra un nuevo usuario en la plataforma con un rol asignado.

Body (JSON):

{
  "nombre": "Juan",
  "email": "juan@mail.com",
  "password": "1234",
  "rol": "admin"
}

GET POST /empleados

Permite listar o registrar la lista de empleados. Requiere encabezado de autenticación.

Headers: x-api-key: mi_api_key_segura

Respuesta GET (JSON):

[
  {
    "id": 1,
    "nombre": "Pedro"
  }
]

GET POST /capital

Permite consultar y realizar ajustes sobre el capital y fondos de la empresa.

Respuesta GET (JSON):

{
  "total_general": 100000,
  "fondo_nomina": 10000
}

5. Formato de Datos

Toda comunicación intercambiada con la API debe estructurarse utilizando el formato estándar JSON.

  • Encabezados: Debe incluir x-api-key para rutas protegidas.
  • Payloads / Body: Objetos en formato application/json.
  • Respuestas: Estructuras estandarizadas en formato JSON.

6. Dirección y Flujo de Datos

El procesamiento de cada solicitud sigue un flujo secuencial a través del stack tecnológico de la aplicación:

Cliente (LAN) ➔ API Flask (192.168.1.100:5000) ➔ MariaDB ➔ Respuesta JSON

7. Diccionario de Datos

Estructura de campos compartida dentro de los modelos del sistema:

Campo Tipo Obligatorio Descripción Ejemplo
id Integer Sí Identificador único del registro 25
nombre String Sí Nombre completo del empleado "Juan"
rol String Sí Rol asignado para permisos "admin"
monto Float No Salario asignado o monto de ajuste 1500.50

8. Ejemplos de Consumo en Red Local

Postman

Configura la solicitud HTTP en la interfaz usando la IP local de tu servidor:

Method: GET
URL: http://192.168.1.100:5000/empleados
Headers: 
  x-api-key: mi_api_key_segura

cURL

curl -X GET http://192.168.1.100:5000/empleados \
  -H "x-api-key: mi_api_key_segura"

Python (requests)

import requests

# Reemplazar 192.168.1.100 por la IP local de la máquina servidor
url = "http://192.168.1.100:5000/empleados"
headers = {
    "x-api-key": "mi_api_key_segura"
}

response = requests.get(url, headers=headers)
print(response.json())

9. Manejo de Errores

En caso de fallos en la solicitud o ejecución, el servidor retornará un objeto de error estándar con un código de estado HTTP adecuado:

{
  "statusCode": 401,
  "message": "API Key inválida"
}
Código Estado Descripción
401 Unauthorized Autenticación fallida o API Key no proporcionada.
404 Not Found El recurso o endpoint solicitado no existe.
500 Internal Server Error Ocurrió un error no controlado en el servidor.
