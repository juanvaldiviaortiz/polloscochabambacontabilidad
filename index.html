Documentación Técnica de la API

Especificaciones para la integración interdepartamental del Departamento de Contabilidad

1. Introducción

La API de Integración de Contabilidad es un servicio REST desarrollado en FastAPI sobre una base de datos SQLite con soporte de claves foráneas. Funciona como nodo centralizador de información financiera, consolidando ventas, comisiones de personal, gastos de campañas de marketing y compras de insumos.

Backend Engine

FastAPI / Uvicorn

Base de Datos

SQLite3 (PRAGMA FK=ON)

Interfaz Web

Streamlit Dashboard

Versión API

v1.2.0

Módulos e Integraciones Clave:

  • Gestión de Personal y Nómina: Registro de empleados, cargos por categoría e integración automática de comisiones en la nómina.
  • Marketing: Registro e historial centralizado de inversiones y gastos publicitaritarios por campaña.
  • Compras e Insumos: Registro de adquisiciones con desglose de impuestos (IVA) interconectado con servicios externos de proveedores y productos.
  • Ventas Integradas: Consolidación de ingresos originados en sistemas de venta externos.

2. Configuración para Pruebas e Integración en Red Local (LAN)

Para permitir que el panel en Streamlit o aplicaciones externas dentro de la red local puedan interactuar con la API, el servidor Uvicorn se ejecuta escuchando en la interfaz 0.0.0.0 en el puerto 8000:

# Comando para iniciar el backend desde la terminal
python api.py
# O ejecutable directamente mediante Uvicorn:
uvicorn api:app --host 0.0.0.0 --port 8000 --reload

Variables de Entorno Configurables:

  • DB_PATH: Ruta del archivo SQLite (Valor por defecto: contabilidad.db).
  • API_URL (en Frontend Streamlit): URL base para consumir el backend (Ejemplo: http://localhost:8000/api/v1 o http://192.168.X.X:8000/api/v1).

3. Arquitectura y CORS

La API dispone de middleware CORS (Cross-Origin Resource Sharing) habilitado totalmente (allow_origins=["*"]), permitiendo solicitudes desde cualquier cliente web o tablero de control en la red.

Adicionalmente, el frontend en Streamlit se conecta con un microservicio de catálogo externo para obtener la lista de proveedores y productos:

Servidor Externo de Inventario/Proveedores: http://192.168.68.157:5000/api/v1

4. Endpoints de la API (/api/v1)

GET /

Verifica el estado del servicio de contabilidad.

Respuesta de éxito (200 OK):

{
  "mensaje": "API de Contabilidad activa y lista para recibir integraciones."
}

GET /api/v1/categorias

Obtiene el catálogo de categorías / cargos de empleados disponibles.

Respuesta de éxito (200 OK):

{
  "1": "Vendedor Senior",
  "2": "Ejecutivo de Ventas",
  "3": "Analista de Marketing",
  "4": "Contador"
}

GET /api/v1/empleados

Retorna la lista detallada de empleados junto con su categoría y horarios.

POST /api/v1/empleados

Registra un nuevo empleado en la base de datos de contabilidad.

Body (JSON):

{
  "nombre": "Carlos",
  "apellido": "Mendoza",
  "edad": 30,
  "categoria_id": 1,
  "turno": "Mañana",
  "horario_inicio": "08:00",
  "horario_fin": "16:00",
  "salario_base": 3500.0,
  "departamento_origen": "Ventas"
}

POST /api/v1/ventas/comisiones

Registra la comisión de un empleado y liquida la nómina acumulando el salario base registrado.

Body (JSON):

{
  "empleado_id": 1,
  "periodo": "2026-10",
  "monto_comision": 450.00
}

GET POST /api/v1/marketing/gastos

Consulta o registra gastos asignados a campañas publicitarias.

Body POST (JSON):

{
  "campaña": "Campaña Redes Q4",
  "proveedor_o_afiliado": "Meta Ads",
  "monto_gasto": 250.00,
  "fecha": "2026-10-09"
}

GET POST /api/v1/compras/insumos

Consulta o registra la adquisición de insumos con cálculo de impuestos.

Body POST (JSON):

{
  "proveedor_id": 1,
  "producto_id": 101,
  "cantidad": 10,
  "precio_unitario": 50.0,
  "total": 500.0,
  "monto_impuesto": 65.0,
  "total_a_pagar": 565.0,
  "fecha": "2026-10-09"
}

5. Formato de Datos

Toda comunicación intercambiada con la API se realiza en formato estándar JSON (Content-Type: application/json). Pydantic valida automáticamente los tipos y rangos de datos de entrada.

6. Dirección y Flujo de Datos

Esquema de integración entre los módulos de negocio y el almacenamiento de contabilidad:

Frontend Streamlit / API Externa ➔ FastAPI REST Controller ➔ Modelos Pydantic ➔ SQLite (contabilidad.db)

7. Diccionario de Datos (Modelos y Tablas)

Estructura de las tablas principales en SQLite:

Tabla: empleados

Campo Tipo DB Validación / Regla Descripción
idINTEGERPRIMARY KEY AUTOINCREMENTIdentificador único del empleado
nombreTEXTNOT NULLNombre(s) del empleado
apellidoTEXTNOT NULLApellido(s) del empleado
edadINTEGERCHECK(edad >= 18 AND edad <= 80)Edad laboral del empleado
categoria_idINTEGERFOREIGN KEY -> categorias_empleado(id)Rol o cargo del empleado
salario_baseREALNOT NULL, >= 0Sueldo base contratado
departamento_origenTEXTNOT NULLÁrea (Ventas, Marketing, Contabilidad)

Tabla: pagos_nomina

Campo Tipo DB Descripción
idINTEGERIdentificador del pago de nómina
empleado_idINTEGERID del empleado asociado
salario_baseREALSalario registrado al momento del pago
monto_comisionesREALMonto adicional acumulado por comisiones
monto_totalREALSuma total a liquidar (Base + Comisiones)
fecha_pagoTEXTFecha de emisión del pago

Tabla: compras_insumos

Campo Tipo DB Descripción
proveedor_idINTEGERID del proveedor (Obtenido de API externa)
producto_idINTEGERID del insumo/producto (API externa)
cantidadINTEGERCantidad comprada (> 0)
precio_unitarioREALPrecio por unidad (> 0)
totalREALSubtotal bruto
monto_impuestoREALMonto correspondiente a impuestos (ej. IVA 13%)
total_a_pagarREALMonto total con impuestos calculados

8. Ejemplos de Consumo

Python (requests) - Registrar Compra de Insumos

import requests

url = "http://localhost:8000/api/v1/compras/insumos"
payload = {
    "proveedor_id": 2,
    "producto_id": 105,
    "cantidad": 50,
    "precio_unitario": 12.5,
    "total": 625.0,
    "monto_impuesto": 81.25,
    "total_a_pagar": 706.25,
    "fecha": "2026-10-09"
}

response = requests.post(url, json=payload)
print(response.json())

cURL - Consultar Empleados

curl -X GET http://localhost:8000/api/v1/empleados

9. Manejo de Errores

FastAPI responde automáticamente con estructuras estandarizadas al encontrar errores de validación de modelos o recursos inexistentes:

// Ejemplo de error 404 (Empleado no encontrado)
{
  "detail": "Empleado con ID 99 no existe."
}

// Ejemplo de error 422 (Unprocessable Entity - Fallo de Validación Pydantic)
{
  "detail": [
    {
      "loc": ["body", "edad"],
      "msg": "ensure this value is greater than or equal to 18",
      "type": "value_error.number.not_ge"
    }
  ]
}
Código Estado Descripción
200 / 201 OK / Created Solicitud procesada o recurso creado correctamente.
404 Not Found El empleado o recurso solicitado no existe en la base de datos.
422 Unprocessable Entity El cuerpo de la solicitud no cumple con los tipos o validaciones requeridas por Pydantic.
500 Internal Server Error Excepción no controlada en la base de datos o servidor backend.
